# DAILY ROOM v0.1.0

一行日記と24時間のタイムライン。今日を、少しだけ残す。

## 公開版を開く

[DAILY ROOM](https://zeekkeezezek.github.io/julius-daily-room/) をPCとスマホから開き、同じGoogleアカウントでログインする。フォルダやNode.jsは公開版の利用には不要だ。

## PCでローカル版を開く

`Start DAILY ROOM.cmd` をダブルクリックするとブラウザで開く。Node.jsが必要だ。君のPCには制作時点でNode.jsがあった。最初の画面で「Googleでログイン」を選ぶ。

PC用のアドレスは `http://localhost:43127/daily-room/`。Googleログインで承認済みのlocalhostを使う。起動用のウィンドウを閉じるとサーバーを止める。HTMLファイルを直接ダブルクリックする方法では起動できない。

試用記録はクラウド用の記録とは別の保存領域にある。以前の試用記録がある場合は、ログイン画面の「この端末の試用記録を開く」からJSONを書き出し、Googleログイン後に「設定 → JSONを読み込む」で移せる。設定から試用記録だけを書き出すこともできる。自動では混ぜない。

以前の版を `http://127.0.0.1:43127/daily-room/` で使っていた場合、そのアドレスを同じブラウザで開いて試用記録を書き出してから、localhost側へ読み込む。ブラウザはlocalhostと127.0.0.1を別の保存先として扱う。どちらの端末記録も消していない。ブラウザのサイトデータを消す前にJSONを別の場所へ残してくれ。

## 操作

- 一行日記は200文字まで。入力のたび端末へ保存し、接続後は短い待ち時間で同期する。
- PCでは時間軸の空白をドラッグして、活動を押すと保存する。補足は活動を押す前に書ける。
- スマホは通常スワイプでスクロール。「指で記録」で選択モードへ切り替える。記録後もそのモードが続くので、スクロールへ戻す時は「記録中・終了」を押す。
- `＋`から開始・終了を選んで記録することもできる。
- 活動を押すと種類・時間・補足を編集できる。削除には確認を出す。
- 重なる記録は確認後に別の列へ並べる。既存の記録は自動変更しない。
- 日付の矢印と日付入力で過去へ移動できる。未来の日は編集しない。
- カレンダーの赤い点は一行日記、青い点はタイムライン。日付を押すとその日のページが開く。
- 設定からJSONを書き出し・読み込みできる。読み込み前の記録はJSONを書き出し、復元用控えとして端末にも残す。日付が同じ記録は確認して置き換える。

## 接続状態

専用Firebase `julius-daily-room` のWeb設定を反映済み。Google認証は有効。Firestoreは東京（asia-northeast1）、Standard editionで作成し、同梱の本人UID限定ルールを公開済み。Rules Playgroundで本人の読み取り許可、未ログインと別UIDの読み取り拒否を確認した。

GitHub Pagesへ公開済み。公開URLで実際のGoogleログインとFirestoreの読み取り接続を確認した。実際の記録の書き込み・PC／スマホ間同期はまだ未確認。現在の設定と残りの手順は [SETUP.md](SETUP.md) にまとめた。

日付ごとに `dailyRoom/{uid}/days/{YYYY-MM-DD}` を保存する。Firestoreの永続オフラインキャッシュに加え、UID別の端末保存と送信待ちリストを持つ。オフラインでは端末へ保存し、オンラインへ戻って全記録の取得を確認した後、トランザクションで日付のrevisionを確認して同期する。

別端末で同じ日が更新されていた場合、古い版を自動送信せず確認を出す。この端末／同期先のどちらを採用するか選び、採用しなかった版もJSONの `recovery` に残す。通常の読み込みでは `days` だけを復元する。復元用控えを戻したい場合は、その版を `days` に移したJSONを読み込める。

同じブラウザ内の別タブは閲覧用になり、同時に端末保存を上書きしない。別タブで編集したい時は先に編集しているタブを閉じ、再読み込みする。

WORK ROOMのリポジトリ・コード・Firebase・記録には変更を加えていない。

## 制作物

- `src/`：アプリ本体
- `dist/`：Firebase設定を反映した完成ビルド
- `public/icons/`：画像生成したオリジナル、192px／512pxアイコン、生成指示の記録
- `firestore.rules`：DAILY ROOM専用のアクセス規則
- `.github/workflows/pages.yml`：手動実行でGitHub Pagesへ公開する設定
- `CHECKS.md`：確認したことと未確認のこと

## 開発

```sh
npm ci
npm run dev
npm test
npm run build
```

Googleログインには、DAILY ROOM専用のWeb設定を `public/firebase-config.json` に用意する。`firebase-config.example.json` は記入例だ。環境変数 `PUBLIC_FIREBASE_CONFIG` にJSONを設定してビルドする方法も使える。

公開用ビルドは相対パスで、GitHub Pagesの `/julius-daily-room/` の下に置ける。サービスワーカーはそのアプリの範囲だけを担当し、アプリの画面と同梱したSDKをオフライン用に保存する。開発モードではサービスワーカーを使わない。
